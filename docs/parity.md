# Feature status

Available features and verification scope for 0.4.35 on Apple Silicon. Automated adapter tests use controlled inputs; they do not establish compatibility with every agent version or a complete model session.

## Changes in 0.4.35

Browsing a completed conversation no longer enrolls it in the live task pool. History-only rollout reconciliation cannot establish activity. Desktop activity is bound to an observed turn, closes on its outcome, and rejects later snapshots of the same completed turn. A concrete terminal turn wins over stale runtime flags; an active runtime without an in-progress turn does not establish work. Regression tests cover archived discovery, changed completion snapshots, stale Working/Attention flags, turn isolation, new work in an old chat, parallel subscriptions and idle recovery. On 2026-10-25, installed 0.4.35 (build 62) was checked by opening three old completed chats without submitting a message. Across 49 live status samples over 50 seconds, none reappeared in Sessions; the current running task remained Working. The replacement preserved 342 History/Usage/preferences files byte-for-byte before relaunch. New-turn and completion behavior were checked with controlled socket fixtures; a separate real new model turn was not submitted.

## Changes in 0.4.34

A managed worker’s missing final hook is recovered from its committed native admission/execution outcome using a private journal of opaque identities. The existing heartbeat reads only its own profile ledger; it never infers success from silence or changes native data. A confirmed interrupted execution closes without success; unknown remains waiting. Generation, epoch and latest-turn checks protect newer work. A real telemetry outage retained a completed receipt until reconnect. A real target-scoped worker restart reproduced stale Working with plugin 1.14; repeating the native interruption with 1.15 automatically closed the old card and restored idle. Host crashes were not exercised.

On 2026-10-24, a separate real scratch task was checked with installed 0.4.34 (build 61) and observer 1.15. Only its verified managed-worker PID received SIGKILL while a safe terminal command was in flight; the gateway process remained alive. The task run recorded `crashed` and its admission settled `interrupted`. The app changed Working → Waiting, then closed that execution and restored the profile to idle without reporting Done or restarting the app. Both delivery queues and the execution journal were empty. The disposable task was archived with its crash result preserved. This covers one managed worker on one remote macOS profile, not host failure or every runtime entry point.

## Changes in 0.4.33

Outcome receipts survive delivery failures and worker exits, without storing task text. Auxiliary calls and unbound tool IDs cannot invent task activity; late events cannot reopen a completed or failed Hermes turn. SSH peer provenance distinguishes remote navigation from a local application failure; notices clear after three seconds. Automated tests cover replay, process restarts, terminal fencing, source ownership and notice expiry. Native execution completion remains separate from successful task acceptance; unmatched historical events are not reclassified from silence.

On 2026-10-24, a real API task on the remote `backend-coder` profile was checked with installed app 0.4.33 (build 60) and plugin 1.14. Its single terminal call waited 20 seconds and returned the expected marker with exit code 0; the native run and admission both completed. Working, Done with the final reply, and Online / No active tasks were visually verified. Read-only status sampling confirmed idle with zero active tasks for more than two minutes and four fresh presence receipts after completion; both delivery queues were empty. This covers one successful API task on one remote macOS profile. Live delivery failure, worker restart, interruption and other entry points were not exercised in this check.

## Changes in 0.4.32

Old unnamed idle sessions no longer retain an extra application row beside a fresh confirmed local profile. Fresh unnamed events and independent working, waiting, approval and failed tasks remain separate. Regression tests cover missing/stale receipts, the 120-second freshness boundary and task activity isolation; the full automated suite passed. Manual UI validation was not repeated for this patch.

## Changes in 0.4.31

Agent identity now separates confirmed local profiles, SSH connector origins and unknown sources. Installation/running-app discovery is a fallback rather than an extra agent beside a fresh local profile. Independent unnamed sessions retain their own presence. Local setup includes a profile selector and a command scoped to its exact home. Automated fixtures passed for 100 local profiles plus two SSH groups of 100 profiles, 900 task records, 100 simultaneous IPC deliveries, source conflicts, connector removal, independent freshness and stable settings/identity preservation. This is controlled-input coverage, not 300 live model sessions. Plugin 1.13 keeps the 1.12 event format and adds native-helper checks and explicit clone identity setup. Native export passed all 79 checks; the local-profile selector was visually inspected using a disposable catalog with 100 named profiles. Physical keyboard/VoiceOver use and hundreds of real model processes remain unverified.


## Verification added in 0.4.30

Memory updates use one brain symbol in History rows, record details and live task labels. Ordinary closed records use an archive symbol; status text and stored terminal states remain unchanged. The full test suite, release archive verification and DMG checks passed. Isolated native History and memory-card fixtures passed in English, Russian and Simplified Chinese; list, detail and 360 pt layouts were visually inspected. These checks use synthetic records and do not establish VoiceOver behavior or rendering on every supported macOS version.

## Verification added in 0.4.29

Goal History reconciliation follows an explicitly completed goal across resumed turns. It updates only the existing original `/goal` record, preserves its content and dates, and leaves ordinary cancelled turns unchanged. Native events and correlated completion receipts, chunked reads, late archive creation and malformed/symlinked input have regression coverage. A read-only check found the completion in the affected local rollout; it did not modify the production archive.

The release build passed isolated History and Usage fixtures in three languages and updater replacement/rollback checks. Current-process Settings captures were inspected in English and Russian; one transient ScreenCaptureKit failure cleared on retry. The native hover/Clear fixture now positions its synthetic pointer inside the panel before opening, and all 15 interaction checks passed.

Keyboard navigation is limited to visible sessions. The companion uses a native button, and a login-item failure no longer triggers a second service request. Navigation has regression coverage; physical keyboard/VoiceOver behavior and login-item failure UI still require manual validation.

Adapter fixtures cover explicit unsuccessful Hermes turns, exact Copilot event-name aliases, a single relay deadline, buffered acknowledgements after peer close and guarded socket recovery. The custom-agent example runs against isolated sockets. This audit did not change installed agent configurations or run new end-to-end model sessions for every provider. Plugin 1.12 must be installed separately in existing remote profiles; publishing the Mac app does not update those profiles.

The subsequent deployment check on 2026-10-23 verified installed app 0.4.29 (build 56), its executable against the release archive and its code signature. The previously stopped goal record had reconciled to `completed` in the working History archive. The live History row was not visually inspected because native UI automation was unavailable. Plugin 1.12 was installed in eight remote profiles: running gateway versions, 15 registered hooks per profile, no load errors and fresh presence in the Mac app were verified. Configuration bytes were preserved; no new model turn was submitted. See [plugin verification](../plugins/hermes/REVISION.md).

A later real API task with plugin 1.12 completed two terminal calls. Working, Done, the final reply and the completed History row were visually verified in the installed app. Four requests were assigned to one task; its 74,453 tokens matched the native ledger, including title generation and without adding cached input twice. The separate Usage detail window remained visually unverified after the automation connection failed. See the same plugin verification report for exact counts and scope.

## Manual validation

Physical audio output, hover feel, Mission Control, all multi-monitor/no-notch/fullscreen combinations and macOS 14–15 rendering require manual validation. Static screenshots do not measure compositor frame rate.

## Not supported

Exact terminal-tab navigation, automatic quiet mode for Focus/lock/screen sharing, Bark, Docker relay, Claude Desktop/Cowork and other providers' account limits.
